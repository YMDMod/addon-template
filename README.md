Аддон представляет собой папку с файлом `manifest.json` и одним или двумя JS-файлами. Аддон взаимодействует
с клиентом через объект `ymd`, предоставляемый модом, и через DOM страницы.

### manifest.json

```json
{
  "id": "my-addon",
  "name": "Мой аддон",
  "version": "1.0.0",
  "description": "Это видно на странице мода и в каталоге.",
  "modVersions": [">=0.1.0 <1.0.0"],
  "dependencies": { "notifications": ">=0.3.0" },
  "settings": [
    { "key": "duration", "type": "number", "label": "Сколько секунд показывать", "default": 4 }
  ]
}
```

| Поле | Обязательное | Назначение |
|---|---|---|
| `id` | да | строчные латинские буквы, цифры и дефис; должен совпадать с именем папки |
| `name`, `version` | да | название и версия в формате `X.Y.Z` |
| `description` | нет | описание на странице мода и в каталоге |
| `modVersions` | нет | версии мода, на которых аддон проверен: `"*"`, `"0.1.0"`, `">=0.1.0 <1.0.0"`. При несовпадении аддон запускается, но пользователь видит предупреждение |
| `dependencies` | нет | аддоны, без которых ваш аддон не работает, с требуемыми версиями. Подробнее — ниже |
| `settings` | нет | настройки, которые мод отображает на странице аддона: `boolean`, `number`, `string`, `select` (для последнего также `options: [{ value, label }]`) |

Остальные сведения мод определяет самостоятельно:

- **Код** — по именам файлов в корне: `main.js` выполняется в главном процессе клиента (Node.js и Electron),
  `renderer.js` — на странице клиента. Требуется хотя бы один из них.
- **Автор** в каталоге — владелец репозитория на GitHub.
- **Состояние** — после установки аддон включён, пока пользователь его не отключит.

### Код на странице (renderer)

Выполняется на странице клиента.

```js
module.exports = {
  start(ymd) {
    ymd.addStyle('.my-badge { color: tomato }');
    ymd.player.onChange((state) => ymd.log('сейчас играет', state.title));
  },
};
```

<details>
<summary><b>Возможности объекта <code>ymd</code></b></summary>

<br>

| | |
|---|---|
| `id`, `apiVersion`, `modVersion`, `clientVersion` | сведения о версиях |
| `settings.get(key)`, `settings.all()`, `settings.set(key, value)`, `settings.onChange(fn)` | настройки аддона |
| `player.getState()` | `{ isPlaying, canMoveBackward, canMoveForward, title, artist, album, artwork }` |
| `player.onChange(fn)` | вызывается при смене трека или состояния плеера |
| `player.play()`, `pause()`, `toggle()`, `next()`, `prev()` | управление плеером |
| `notify(text, { type })` | уведомление; `type` — `info`, `success`, `error` или `progress` |
| `on(event, fn)`, `emit(event, payload)` | общая шина событий между страницей, main-частью и другими аддонами |
| `expose(api)`, `use(id, range?)` | предоставление своего API другим аддонам и использование чужого, см. «Библиотеки и зависимости» |
| `dom.observe(fn)` | вызов `fn` при изменении DOM (не чаще одного раза за кадр) |
| `dom.each(selector, fn)` | вызов `fn` для каждого нового элемента по селектору, включая перерисованные клиентом |
| `addStyle(css)` | добавление стилей |
| `setTimeout`, `setInterval` | стандартные таймеры, автоматически снимаемые при отключении аддона |
| `guard(fn)` | обёртка для собственных обработчиков событий браузера, см. «Обработка ошибок» |
| `ui.addPage({ id, title, render(container) })` | собственная вкладка на странице мода; `render` может вернуть функцию, вызываемую при уходе с вкладки |
| `onDispose(fn)` | действие при отключении аддона |
| `log(...)` | запись в журнал мода |
| `diagnostics()` | промис со сведениями о версиях, путях к журналу и данным, состоянии аддонов |

</details>

Селекторы элементов клиента следует строить по атрибутам `data-test-id` и `aria-label`. Классы вида
`Name_class__a1b2c` меняются от сборки к сборке.

### Код в главном процессе (main)

```js
module.exports = {
  activate(api) {
    api.electron.globalShortcut.register('MediaPlayPause', () => api.player.toggle());
  },
  deactivate() {},
};
```

Объект `api` аналогичен `ymd`, но не содержит `dom`, `addStyle`, `ui` и таймеров. Дополнительно в нём доступны:

- `electron` — модуль Electron (`globalShortcut`, `BrowserWindow`, `shell` и др.);
- `mainWindow()` — главное окно клиента;
- `dataDir` — папка для файлов аддона.

Код main-части выполняется с полными правами, поэтому такие аддоны при включении в каталог проверяются
особенно тщательно.

### Уведомления

```js
ymd.notify('Сохранено', { type: 'success' });
```

Индикатор прогресса, кнопки и закрытие уведомлений из кода описаны в
[README аддона «Уведомления»](https://github.com/YMDMod/notifications#для-разработчиков-аддонов).

### Библиотеки и зависимости

Любой аддон может предоставить своё API: `ymd.expose({ ... })` на странице или `api.expose({ ... })` в main.
Другие аддоны получают его через `use`:

```js
const toasts = ymd.use('notifications');          // версия берётся из dependencies
const lyrics = ymd.use('lyrics-core', '>=2.0.0'); // или указывается явно
```

`use` возвращает `null`, если аддон не установлен, отключён или его версия не подходит. Вызывайте `use`
в момент обращения к API, а не однократно при запуске: библиотека может быть обновлена или перезапущена.

Если ваш аддон не может работать без другого аддона, укажите его в `dependencies`:

```json
"dependencies": { "notifications": ">=0.3.0" }
```

В этом случае мод:

- запускает зависимость раньше вашего аддона;
- не запускает ваш аддон, если зависимость отсутствует, отключена или устарела, и указывает причину
  в карточке аддона;
- при установке из каталога запрашивает подтверждение пользователя и устанавливает недостающие зависимости
  вместе с вашим аддоном.

### Обработка ошибок

Исключение в `start` или `activate`, в обработчике шины, в таймере или внутри `guard` отключает аддон
до перезапуска клиента. В карточке аддона отображается статус «Ошибка» с описанием, при этом мод и остальные
аддоны продолжают работу. Повторно включить аддон можно переключателем.

Собственные обработчики (`addEventListener` и т. п.) модом не отслеживаются. Оборачивайте их в `ymd.guard`,
чтобы ошибка в них также отключала только ваш аддон:

```js
document.addEventListener('keydown', ymd.guard(onKey));
```

### Публикация в каталоге

Добавьте репозиторию топик `ymdmod-addon` и опубликуйте релиз с тегом `vX.Y.Z`, совпадающим с версией
в `manifest.json`. Дальнейшие действия выполняет робот каталога — подробнее в
[YMDMod/catalog](https://github.com/YMDMod/catalog).

У репозитория шаблона топик намеренно не задан, чтобы сам шаблон не попал в каталог. Добавьте топик
в своём репозитории.
