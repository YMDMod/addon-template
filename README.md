Аддон — это папка с `manifest.json` и одним-двумя JS-файлами. Мод находит её, показывает на странице мода и
запускает. Работает аддон через объект `ymd`, который ему даёт мод, и через обычный DOM страницы. Лезть во
внутренности минифицированного кода Яндекса не нужно и не стоит: они меняются в каждой сборке.

Проверять удобно прямо в клиенте: страница мода → «Аддоны» → «Установить из папки…».

### manifest.json

```json
{
  "id": "my-addon",
  "name": "Мой аддон",
  "version": "1.0.0",
  "description": "Одна строка — её видно на странице мода и в каталоге.",
  "author": "Ваше имя",
  "apiVersion": 1,
  "modVersions": [">=0.1.0 <1.0.0"],
  "dependencies": { "notifications": ">=0.3.0" },
  "defaultEnabled": true,
  "main": "main.js",
  "renderer": "renderer.js",
  "settings": [
    { "key": "duration", "type": "number", "label": "Сколько секунд показывать", "default": 4 }
  ]
}
```

| Поле | Нужно? | Что это |
|---|---|---|
| `id` | да | латиница в нижнем регистре, цифры и дефис. Должен совпадать с именем папки |
| `name`, `version` | да | название и версия `X.Y.Z` |
| `apiVersion` | да | версия API мода, сейчас `1`. С другой версией аддон не загрузится |
| `description`, `author` | нет | видны на странице мода и в каталоге |
| `modVersions` | нет | на каких версиях мода вы аддон проверяли: `"*"`, `"0.1.0"`, `">=0.1.0 <1.0.0"`. Если не совпадает, аддон всё равно запустится, но пользователь увидит предупреждение |
| `dependencies` | нет | другие аддоны, без которых ваш не работает, с версиями. Подробнее ниже |
| `type` | нет | `addon` (по умолчанию) или `library` — для аддонов, которые в основном отдают API другим |
| `defaultEnabled` | нет | включён ли аддон сразу после установки |
| `main` | нет | файл, который работает в главном процессе клиента (Node.js и Electron) |
| `renderer` | нет | файл, который работает на странице клиента |
| `settings` | нет | настройки, которые мод сам нарисует на странице: `boolean`, `number`, `string`, `select` (для него ещё `options: [{ value, label }]`) |

Хотя бы один из `main` и `renderer` должен быть.

### Код на странице (renderer)

Выполняется на странице клиента.

```js
module.exports = {
  start(ymd) {
    ymd.addStyle('.my-badge { color: tomato }');
    ymd.player.onChange((state) => ymd.log('сейчас играет', state.title));
  },
  stop() {},
};
```

`stop` писать необязательно: всё, что вы создали через `ymd` (подписки, стили, таймеры, вкладки), мод уберёт
сам, когда аддон выключат.

<details>
<summary><b>Что есть в <code>ymd</code></b></summary>

<br>

| | |
|---|---|
| `id`, `apiVersion`, `modVersion`, `clientVersion` | версии |
| `settings.get(key)`, `settings.all()`, `settings.set(key, value)`, `settings.onChange(fn)` | настройки аддона |
| `player.getState()` | `{ isPlaying, canMoveBackward, canMoveForward, title, artist, album, artwork }` |
| `player.onChange(fn)` | вызывается при смене трека или состояния |
| `player.play()`, `pause()`, `toggle()`, `next()`, `prev()` | управление плеером |
| `notify(text, { type })` | показать уведомление, `type` — `info`, `success`, `error` или `progress` |
| `on(event, fn)`, `emit(event, payload)` | общая шина событий: между страницей, main-частью и другими аддонами |
| `expose(api)`, `use(id, range?)` | поделиться своим API с другими аддонами и взять чужой, см. «Библиотеки» |
| `dom.observe(fn)` | `fn` вызывается, когда меняется DOM (не чаще раза за кадр) |
| `dom.each(selector, fn)` | `fn` для каждого нового элемента по селектору, в том числе перерисованного клиентом |
| `addStyle(css)` | добавить стили |
| `setTimeout`, `setInterval` | как обычные, но снимаются сами при выключении аддона |
| `guard(fn)` | обёртка для своих обработчиков событий браузера, см. «Если аддон упал» |
| `ui.addPage({ id, title, render(container) })` | своя вкладка на странице мода. `render` может вернуть функцию, которая вызовется при уходе с вкладки |
| `onDispose(fn)` | что сделать при выключении аддона |
| `log(...)` | запись в лог мода |
| `diagnostics()` | промис с версиями, путями к логу и данным, статусами аддонов |

</details>

Селекторы для DOM клиента берите по `data-test-id` и `aria-label`. Классы вида `Name_class__a1b2c` меняются
с каждой сборкой клиента.

### Код в главном процессе (main)

```js
module.exports = {
  activate(api) {
    api.electron.globalShortcut.register('MediaPlayPause', () => api.player.toggle());
  },
  deactivate() {},
};
```

`api` похож на `ymd`, только без `dom`, `addStyle`, `ui` и таймеров. Зато в нём есть:

- `electron` — модуль Electron целиком (`globalShortcut`, `BrowserWindow`, `shell`, …);
- `mainWindow()` — главное окно клиента;
- `dataDir` — папка, куда аддон может складывать свои файлы.

Код в main работает с полными правами, поэтому к таким аддонам при проверке в каталоге присматриваются
внимательнее.

### Уведомления

```js
ymd.notify('Сохранено', { type: 'success' });
```

Прогресс, кнопки и закрытие из кода — в [README «Уведомлений»](https://github.com/ymdmod/notifications#для-авторов-аддонов).

### Библиотеки и зависимости

Любой аддон может поделиться своим API: `ymd.expose({ ... })` на странице или `api.expose({ ... })` в main.
Другие аддоны получают его через `use`:

```js
const toasts = ymd.use('notifications');          // версия берётся из dependencies
const lyrics = ymd.use('lyrics-core', '>=2.0.0'); // или указывается явно
```

`use` возвращает `null`, если такого аддона нет, он выключен или его версия не подходит. Вызывайте `use`
в тот момент, когда API нужен, а не один раз при старте: библиотеку могут обновить или перезапустить.

Если без другого аддона ваш не может работать, пропишите его в `dependencies`:

```json
"dependencies": { "notifications": ">=0.3.0" }
```

Тогда мод:

- запустит зависимость раньше вашего аддона;
- не запустит ваш аддон, пока зависимости нет, она выключена или слишком старая, и покажет причину
  в карточке;
- при установке из каталога спросит пользователя и поставит недостающие зависимости вместе с вашим аддоном.

Аддоны, которые в основном нужны другим, помечайте `"type": "library"` — в списке у них будет метка
«Библиотека».

### Если аддон упал

Исключение в `start` или `activate`, в обработчике шины, в таймере или внутри `guard` выключает аддон до
перезапуска клиента. В его карточке появится статус «Ошибка» с текстом, а мод и остальные аддоны продолжат
работать. Включить аддон обратно можно переключателем.

Обработчики, которые вы вешаете сами (`addEventListener` и т. п.), мод не видит. Оберните их в `ymd.guard`,
чтобы ошибка в них тоже выключала только ваш аддон:

```js
document.addEventListener('keydown', ymd.guard(onKey));
```

### Как попасть в каталог

Добавьте репозиторию топик `ymdmod-addon` и выпустите релиз с тегом `vX.Y.Z`, где версия совпадает с
`manifest.json`. Дальше всё сделает робот — подробности в [ymdmod/catalog](https://github.com/ymdmod/catalog).

У этого репозитория топика нет специально, чтобы сам шаблон не попал в каталог. Не забудьте добавить его у себя.
